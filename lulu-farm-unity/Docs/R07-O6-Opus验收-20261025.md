## 性能（O6 三个会话）

| 会话 | 运行时 mean / p95 / max (ms) | 墙钟帧间隔 mean / p95 / max (ms) | GPU p95 (FrameTiming) | ≥50 ms 帧 | ≥400 ms 帧 |
|---|---|---|---|---|---|
| 主会话 15 分钟 | 8.55 / 9.44 / 90.7 | 8.55 / 9.69 / 91.5 | 6.93 | 13（其中 12 为呈现等待、CPU 空闲；另 1 帧 50 ms） | 0 |
| 风动关 5 分钟 | 8.57 / 8.37 / 3727 | — | 7.25 | 8 | 5（0.55–1.09 s，均为呈现等待、渲染线程空闲；集中在 93–99 s 和 309 s） |
| 风动开 5 分钟 | 8.40 / 8.93 / 173 | — | 6.85 | 3（含一次 165 ms，阴影准备 78 ms） | 0 |

- 主会话：除了第 0 秒的 Profiler 截图帧（186 ms，只在时间线里，不在运行时样本里），整整 15 分钟没有超过 100 ms 的帧，`unscaledDeltaExceedsWallFrames` = 0。r06 的不通过标准是 8 个窗口有 >100 ms 的帧（其中 3 个 >1 s），O6 主会话没有出现这种情况。
- 风动关会话里出现了约 1 s 的停顿，和 O2 报告里的类型相同：主线程在等上一帧呈现，渲染线程空闲，不是游戏自身的计算量。运行时样本里的 3727 ms 是 O2 已经说明过的 unscaledDeltaTime 累加假象（那个窗口墙钟只有 1.53 s）。这类停顿仍然偶发，不能保证不再出现。
- 风动开和关的 GPU p95 分别是 6.85 和 7.25 ms，所以风动不是 D6 GPU 上升（p95 6.8→10.2 ms）的原因。O6 的 GPU p95 回到 6.93 ms，最可能的原因是透明淡出（ZWrite 关、多层叠加）换成了不透明抖动，但这个原因未单独证明。

## O3 修订（在 O7 生效，O6 不再重跑）

`OcclusionDither-r09`：
- 网点改为交错梯度噪声，不再是重复的 4×4 网格。
- 露露周围留一个完全透明的"钥匙孔"（视角 7°–15°），焦点由 `FarmThirdPersonCamera` 每帧写入 `_FarmFadeFocusWS`。
- 钥匙孔以外的覆盖率从 25% 降到 15%。
- 影子保留。O6 路线 024 里那片暗色区域是房子的真实投影；D6 的透明淡出关掉了投影，所以 D6 那张反而偏亮。

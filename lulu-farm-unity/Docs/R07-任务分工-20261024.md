## 1. 分工原则

- **DeepSeek**：照现有流程和明确参数执行的工作。包括在 Mac 上跑 Blender、Unity Editor CLI、构建、截图路线、Profiler 采集，以及摆放、开关设置、简单脚本。
- **Opus**：需要判断或算法设计的工作。包括角色网格与绑定、根因诊断、渲染问题、美术方向和参数、每项交付的验收，以及最终整合。
- 交接方式：DeepSeek 每做完一项，把**证据**（日志、截图、metrics、改动文件列表）放到 `Evidence/r07/<任务编号>/`，再写一份 `REPORT.md`，说明做了什么、哪些没做成、实际看过哪些截图。Opus 根据这些文件验收。
- **不许宣告通过**：DeepSeek 只能写"已完成，待 Opus 验收"。技术通过、视觉初审、用户美术认可三者分开记录。
- **不改动**：原件、已认可的版本、r06 交付包、locomotion-r08、`lulu-studio` 里所有已有的 review 版本。要改就另存新版本。
- 场景内容只改 Builder（`FarmProjectBuilder.cs` / `FarmLandscapePolish.cs`）和导入策略，不要手改生成后的场景，否则下次重建会丢。
- 同一个问题连续两轮没修好，就停下，留下对照和说明交给 Opus，不要接着调小参数重试。

## 3. DeepSeek 任务详细说明

### D1 S02 谷仓派生和入场
1. 参照 S01 的流程：用 `lulu-studio/tools/unity_assets/` 下的 atlas 流程（`run_atlas.py` → `process_bvh.py`，`run_facility_lods.py`）生成 `S02` 的 atlas-r01 和 atlas-lod1-r01。Blender 路径：`/Users/haowen/.codex/runtimes/blender/Blender.app/Contents/MacOS/Blender`。如果 manifest 或 interfaces 需要登记 S02，就仿照 S01 补上，不要改 S01 的记录。
2. 目标：LOD0 不超过约 4 万三角面，LOD1 不超过约 1.2 万；贴图 2K 以内。原件不动。
3. 用 `lulu-farm-unity/Tools/sync_assets.py` 同步，在 `asset-registry.json` 增加 S02（字段照 S01 填；worldHeight 先设 3.0）。
4. 在 `FarmProjectBuilder.cs` 的 Pasture 部分放置。初始建议：位置约 `(1.8, 0, 0.2)`，大门朝牧场门（-Z 方向）；不能挡住动物和饲料槽；必要时把羊往前挪。加 Footprint 和一个盒状碰撞（门洞不能进入）。
5. 证据：五视图渲染（材质 + 灰模）、metrics.json、牧场门口和总览同机位截图，跟 r06 同机位对比。

### D2 渲染设置
**以 `Docs/r07-ground-shading-spec.md` 第 C 节为准**（已由 Opus 写好，替换下面这组初始值）。下面保留原始初始值，仅供参考。

- 在 `DesktopURP.asset` / `FarmDesktopRenderer.asset` 里：打开 SSAO（强度约 0.6，半径约 0.3，降采样关），软阴影开，阴影距离约 40，四级级联。
- 全局 Volume：Tonemapping 用 ACES（如果偏灰就换 Neutral，两张都截图），Color Adjustments 饱和度 +12、对比度 +8，Bloom 阈值 1.1、强度 0.25，加轻微暗角 0.15。
- 主光改成暖色（约 #FFF1DC），环境光改为渐变（天空 #CFE8FF、地平线 #EAF3D6、地面 #8FAE6A）。
- 手机档（MobileURP）先不开 SSAO 和 Bloom。
- 证据：12 个固定机位改前改后各一张，加 15 分钟性能对比（同 r06 条件）。

### D3 地面和道路
按 `Docs/r07-ground-shading-spec.md` 第 B 节执行（已写好，可以开始）。DeepSeek 不要自己设计着色方案。

### D4 装饰批量摆放
1. 新写一个 `FarmDecorScatter.cs`（Editor），由 Builder 调用，用固定随机种子，保证可复现。
2. 排除区：道路、田地、牧场内部动物活动区、池塘水面、码头、房屋和摊位的 Footprint，再各留 0.4 m。
3. 摆放内容（只用已导入的库资源）：
   - 道路两侧和围栏外沿：小灌木加白花，每米 0.3–0.5 个；
   - 外围：圆树和梨树围一圈，间距 3–5 m；
   - 草地：零散的花丛和石头；
   - 房屋前后：花丛。
4. 摆放物要有随机旋转和 0.85–1.15 倍随机缩放，不要排成直线。
5. 小物件不加碰撞，树干加胶囊碰撞。
6. 证据：总览图（固定检查机位）、8 个路线点截图、实例数量和三角面统计、性能对比。

### D5 界面整理
- 增加"正常模式 / 调试模式"开关，默认正常模式。
- 正常模式隐藏底部的录制、帧数、按键提示，顶栏只保留游戏标题和必要按钮（"检查"按钮移到调试模式）。
- 按键提示改成开局显示 5 秒后淡出。
- 发布构建不要带 Development Build 水印（调试构建保留）。
- 证据：两种模式的截图。

### D6 动感
- 草、灌木、树冠：顶点着色器风吹摆动，幅度小，树干不动。必须可以在画质设置里关闭。
- 动物：原地呼吸起伏和偶尔转头（程序动画，不做 AI），每只动物的相位随机。
- 粒子：蝴蝶 3–5 只，在花丛附近；水面偶尔泛起的小波纹。
- 环境音：鸟叫和水声，音量低，可以关闭（音频素材需要是可商用的，记录来源和授权）。
- 证据：短录像加性能对比。

### D7 执行类
- Profiler 采集方法按 `AGENT-HANDOFF-20261024.md` 第 5 节：同设备、同档位、无截屏、15 分钟，保存 `.data` 文件和导出的时间线，**不要做分析结论**，交给 Opus 分析。
